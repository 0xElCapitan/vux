## Learnings

- [Review technique — gate scoping] A fail-closed gate built from `find <fixed-dir>` / `grep -r <fixed-dirs>` enforces a repo-wide claim only where it looks; test gates on the **location** axis (plant a violating artifact outside the scan roots), not only the **content** axis (byte mutation). Demonstrate empirically and revert with a proven-identical `git status` — reading the source alone invites "but another gate covers it". → `skills-pending/fail-closed-gate-scope-probe`
- [Review technique — reproduction claims] "Reproduced" verified by re-running the project's own test proves only self-consistency; the test's literal and the authority's constant are two copies that can diverge. Recompute with an implementation the project does not own, self-validated against published vectors first, and compare against the **authority's** value. Read build semantics off the artifact metadata, not the config. → `skills-pending/independent-constant-reproduction`
- [Implementation technique — closing a scoping gap] Inverting a directory-scoped gate to default-deny **creates a new hole**: the prune/exclusion list you must add to skip build output is now the single place a bypass can hide, and a too-broad entry makes the check pass *because it is looking at nothing* — green, exactly like the bug being fixed. Guard it by asserting the walk still classifies every authority row (`verify-census.sh:99-104`). Corollary: never prune the conventional dependency directories (`lib/`, `node_modules/`) — an unauthorized dependency landing there is the thing being caught. → `skills-pending/default-deny-source-boundary` (implementation counterpart to `fail-closed-gate-scope-probe`, which is the detection side)
- [Attribution on uncommitted trees] When a node's work is entirely untracked, `git status`/`git diff` cannot attribute anything — mtime windows (`find -newermt <node-start>`) are the only mechanical attribution signal for separating pre-existing working-tree dirt from the node's own mutations. Used to confirm README/TPN dirt predated Sprint 1. (Technique noted; not extracted — direct application, no investigative depth.) **Refined 2026-08-11 at `/audit-sprint sprint-1`: the window is also the technique's failure mode** — `-mmin -40` implicated a vendored file and two review artifacts that were the *previous* nodes' writes (mtimes 23:40–23:48; the audit began ~23:57). Anchor to the node's first tool call, then decide on content, never on mtime. → `skills-pending/audit-subject-fingerprint-under-agent-telemetry`
- [Audit technique — severity triage] A detector blind spot is a necessary but never sufficient condition for a vulnerability: detector and protected consumer are built on the same primitives, so their blind spots are usually **correlated**. Classify a carried-forward finding by running the *consumer* in an isolated scratch project, testing both reachability modes (auto-discovery and explicit reference), and reading the verdict off emitted artifacts + resolver diagnostics — not off the exit code. This refuted N-2 (`Foo.SOL` is invisible to Foundry too: "Unable to resolve imports") and confirmed N-1 (out-of-root `.sol` compiles and emits when imported) from the same experiment. Variant for pin findings: reproduce the constant under a *deliberately different* toolchain version (init-code hash reproduced under forge 1.5.0 vs pinned v1.0.0 ⇒ solc-determined ⇒ loose Foundry assertion is LOW). → `skills-pending/gate-gap-reachability-triage`
- [Loa lifecycle — verdict without closure] A command wrapper and its skill are two artifacts with two permission surfaces, and only the wrapper carries lifecycle closure. `/audit-sprint` declares `COMPLETED` + ledger + index as `outputs:`, while `auditing-security` is `write_files: false` with `disallowed-tools: [Write, Edit]` — so the skill never persists its own report and artifact persistence is architecturally the *caller's* job. A bounded caller can therefore run the native methodology and verdict contract with every closure effect suppressed, validated by `verdict-derive.sh --gate audit`. Corollary hazard: formally invoking a pure-review skill removes the Write tool needed to save the verdict, converting a completable audit into a forced `HITL_REQUIRED`. → `skills-pending/gate-verdict-without-lifecycle-closure`
- [Probe cleanup under the destructive-bash fence] `block-destructive-bash.sh` `FR-2-AMBIGUOUS` blocks `rm -rf`/`rm -f` on variable paths (`"$PROBE"`), hidden names (`.audit-probe.sol`), and bare file paths — accepted form is an explicit visible subdir (`rm -rf ./contracts/`). For probe *files*, `mv` to a scratchpad trash dir instead of `rm`. (Not extracted — the block message states the remedy verbatim, so it fails the Discovery Depth gate.)

## Technical Debt

- Ledger flock incompatibility on this Windows host, refined 2026-08-10: MSYS bash FDs do not survive the native scoop-shim boundary at all, so util-linux-style `flock -w N <fd>`/`flock -u <fd>` cannot work here even with arg adaptation. Session workaround (per prior note, now sharpened): scratchpad PATH shim that **no-ops FD-form calls** (exit 0) and passes FILE-form calls through — safe because sessions are single-writer and `_write_ledger` keeps atomic tmp+mv semantics. Recurs at every ledger mutation (sprint registration, archive) — re-apply shim or install util-linux flock. Candidate upstream /feedback; System Zone not modified. (2026-08-10 addendum: the shim's PATH entry MUST be MSYS-form `/c/...` — a Windows-style `C:/...` entry splits at the drive colon and silently bypasses the shim; a bypassed/failed `_write_ledger` is harmless — the lock is acquired before backup/write, so the ledger file is never touched.)
